# 성남 다문화 아빠 히어로즈

다문화 가정의 아빠가 하루 1분짜리 작은 미션으로 아내·자녀·가족과 가까워지도록 돕는 모바일 웹 앱입니다.
미션을 완료하면 가족의 반응을 기록하고, 포인트(성남사랑상품권)와 배지를 받습니다.

- 서버와 빌드 도구 없이 동작하는 정적 PWA (HTML · CSS · JavaScript ES 모듈)
- 한국어 · English · Tiếng Việt · 中文 4개 언어 지원
- 외부 라이브러리 0개, 단위 테스트 54개

## 실행

```bash
npm start     # http://localhost:5173
npm test      # 단위 테스트 (Node 20 이상, 설치할 패키지 없음)
```

ES 모듈을 쓰기 때문에 `index.html`을 더블클릭해서는 열리지 않고, 위처럼 로컬 서버가 필요합니다.
`main` 브랜치에 push하면 GitHub Actions가 테스트를 돌리고, 통과했을 때만 GitHub Pages에 배포합니다.

## 구조

```
index.html            앱 뼈대 (상단바, 하단 탭, 바텀시트)
sw.js                 서비스 워커 (오프라인 지원)
css/style.css         디자인 토큰과 컴포넌트
js/
  main.js             상태 저장소 연결, 라우팅, 사용자 동작 처리
  core/               화면과 무관한 순수 로직 (테스트 대상)
    domain.js         포인트, 배지, 연속 기록, 주간·월간 집계
    recommend.js      오늘의 미션 추천
    shuffle.js        역할 바꾸기용 셔플
    store.js          상태 저장소와 localStorage 저장
    html.js           자동 이스케이프 템플릿
    i18n.js           다국어 처리
  data/               미션·배지 목록, 번역, 예시 데이터
  ui/                 화면 마크업 (상태를 받아 HTML을 돌려주는 함수)
tests/                node:test 단위 테스트
```

의존 방향은 `ui → core → data` 한쪽으로만 흐릅니다. `core/`는 DOM을 전혀 건드리지 않아서 브라우저 없이 Node에서 그대로 테스트합니다.

## 설계에서 신경 쓴 부분

### 1. 상태는 하나, 나머지는 전부 계산

저장하는 것은 "완료한 미션 기록(`entries`)" 하나뿐이고, 포인트·배지·연속 기록·주간/월간 통계는 모두 이 기록에서 순수 함수로 계산합니다.
처음 버전은 `totalPoints`, `pinkMissions` 같은 전역 변수를 따로 두고 손으로 맞췄는데, 그 탓에 화면의 12,000P와 실제 기록 합계(4,000P)가 어긋나 있었습니다. 지금 구조에서는 값이 어긋날 수 없습니다.

화면은 `store.update()`로만 상태를 바꾸고, 저장소가 구독자에게 알려 화면을 다시 그립니다(단방향 데이터 흐름).

### 2. 미션 추천 (`core/recommend.js`)

9개 미션 각각에 네 항목의 점수를 더해 가장 높은 것을 추천합니다.

| 항목 | 범위 | 의미 |
|---|---|---|
| balance | 0 ~ 3 | 최근 14일 동안 덜 한 대상(아내/자녀/가족)일수록 높음 |
| timeFit | 0 ~ 2 | 평일 낮엔 1분 미션, 평일 저녁엔 10분, 주말엔 30분 미션 |
| novelty | -2 ~ 0.5 | 최근 3일 안에 한 미션은 감점, 한 번도 안 한 미션은 가점 |
| momentum | 0 ~ 1 | 쉬었다 돌아오면 쉬운 미션, 연속 3일 이상이면 더 어려운 미션 |

어떤 항목 때문에 뽑혔는지를 "요즘 가족 미션이 적었어요" 같은 문장으로 함께 보여 줍니다. 난수가 없어서 같은 입력에는 항상 같은 추천이 나오고, 그래서 테스트할 수 있습니다.

### 3. 역할 바꾸기 게임과 Sattolo 알고리즘 (`core/shuffle.js`)

"아무도 자기 자신 역할을 받지 않는다"는 조건이 필요합니다. 일반 Fisher–Yates 셔플은 자기 자신이 나올 수 있고, 처음 버전의 "무작위 칸만큼 회전"은 조건은 지키지만 가능한 배치 중 일부만 나옵니다.
Sattolo 알고리즘은 교환 대상을 `0 ≤ j < i`로 한 칸 줄여 길이 n의 순환 순열을 균등하게 뽑습니다. 순환 순열에는 고정점이 없으므로 조건이 항상 성립합니다. 시드가 있는 난수 생성기(mulberry32)로 n=2~8, 시드 200개에 대해 검증합니다.

### 4. XSS 방지 (`core/html.js`)

처음 버전은 사용자가 쓴 글을 `innerHTML`에 그대로 넣어서, 다이어리에 `<img onerror=...>`를 적으면 스크립트가 실행됐습니다.
지금은 모든 마크업을 `` html`...` `` 태그드 템플릿으로 만들고, 끼워 넣는 값은 기본적으로 이스케이프합니다. 이스케이프를 깜빡할 수 없는 구조입니다.

### 5. 저장과 오프라인

- **스키마 버전**: 저장 데이터에 버전을 두고, 읽을 때 `migrate()`를 거칩니다. 깨졌거나 모르는 데이터면 기본값으로 시작합니다.
- **사진 압축**: 휴대폰 사진은 한 장에 수 MB인데 localStorage는 전체 약 5MB입니다. 캔버스로 긴 변 720px JPEG로 줄여 저장하고, 그래도 용량이 넘치면 사진만 빼고 기록은 남깁니다.
- **서비스 워커**: 네트워크 우선, 실패하면 캐시. 온라인에서는 항상 최신 배포본을 받고, 신호가 없는 곳에서도 마지막으로 연 화면이 열립니다.
- **날짜**: 하루 단위 계산은 밀리초 덧셈이 아니라 달력 연산으로 합니다. 타이머는 틱을 세지 않고 종료 시각과의 차이를 표시해 탭이 멈췄다 돌아와도 틀어지지 않습니다.

### 6. 다국어 (`core/i18n.js`)

문구는 전부 `data/locales/*.js`에 있고, 코드에는 키만 있습니다. 날짜·숫자·"5분 전"·언어 이름은 번역하지 않고 브라우저의 `Intl` API에 맡깁니다.
테스트가 ① 네 언어의 키가 정확히 같은지 ② `{name}` 같은 자리표시자가 빠지지 않았는지 ③ 코드에서 쓰는 키가 실제로 있는지를 확인합니다.

## 사용자를 위한 디자인

대상은 30~50대 아빠, 그중 일부는 한국어 읽기가 편하지 않은 외국 출신 아빠입니다.

- **할 일은 하나만 크게**: 홈 첫 화면에 추천 미션 하나와 "시작하기" 버튼. 9개 미션 목록은 그 아래에 둡니다.
- **글쓰기 부담 줄이기**: 미션 인증에서 긴 글 두 개가 필수였던 것을, 버튼 한 번(😊 웃었어요 / "말해줘서 고마워")으로 끝낼 수 있게 했습니다. 글은 선택입니다.
- **읽기 쉬운 화면**: 밝은 배경에 진한 글씨(WCAG AA 대비), 기본 글자 17px, 설정에서 3단계 확대. 모든 크기가 rem이라 화면 전체가 함께 커집니다.
- **누르기 쉬운 버튼**: 모든 터치 영역 48px 이상.
- **색에만 의존하지 않기**: 핑크/그린/옐로우 미션은 작은 색 표시 옆에 항상 "아내에게" 같은 글자를 함께 둡니다.
- **장식 줄이기**: 카드·그림자·알약 모양·장식용 이모지 없이, 글자 크기와 굵기, 여백, 1px 구분선으로 위계를 만듭니다. 강조색은 하나만 씁니다.
- **언어 버튼은 항상 상단에**: 언어 이름은 그 언어로 표시해서(Tiếng Việt, 中文) 화면을 못 읽어도 찾을 수 있습니다.
- **아내의 모국어로 말하기**: 베트남어·중국어·필리핀어·일본어·태국어·영어 표현을 한글 발음과 함께 보여 주고, 버튼을 누르면 읽어 줍니다(Web Speech API).
- **접근성**: 시맨틱 요소(`button`, `dialog`, `nav`), 키보드 초점 표시, 스크린 리더용 라벨, 다크 모드, 동작 줄이기 설정 존중.

## 아직 없는 것

- 서버가 없어서 기록과 커뮤니티 글은 각자의 기기에만 저장됩니다. 포인트 지급, 추천 코드, 모임 신청도 화면만 있는 체험 기능입니다.
- 알림은 미리보기만 있고 실제 푸시는 보내지 않습니다.
- 베트남어·중국어 번역과 아내의 모국어 표현은 원어민 검수를 거치지 않았습니다.
